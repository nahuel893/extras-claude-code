## In flight: openskin follows external theme changes (`fix/openskin-follow-settings`)

The problem:

- The desktop theme switcher edits `pluginConfigs["openskin@extras-claude-code"].options` in `~/.claude/settings.json`.
- Open sessions don't re-read plugin options edited from outside, so they keep the old colors until `/reload-plugins`.
- `/skin` also overwrote `panelBackground` with stale in-memory values.

The goal:

- openskin watches `settings.json`, and when its options change, it applies them to itself with `$.config.set` (which reloads the module).
- `/skin` stops clobbering fields it does not own.
- Release 0.7.1, bumping both `marketplace.json` and `plugin.json`.

When the previous session ended, the agent was writing `plugins/openskin/tests/follow.test.tsx` (untracked) and had no commits yet. If it never finished:

- Check `git status` on that branch.
- Read the test and continue test-first.
- Run all four mods' tests before merging.

Until it lands, the workaround is `/reload-plugins` after switching the theme.
