## Done: openskin follows external theme changes (`fix/openskin-follow-settings`)

The cause was not what we assumed. Claude Code 2.1.310 already follows outside edits of `settings.json`, symlink included, but only in sessions started after the file became a symlink. Sessions started before that never see later edits. And any `$.config.set` in such a session writes its whole stale copy of the settings back, which is what reverted `panelBackground`.

The fix:

- `hooks/follow.ts`: a 1.5 s timer compares openskin's options and `.theme` in the file with the ones the module has. If they still differ one tick later, it runs `/reload-plugins` through `$.command.run`. It never writes settings and reloads at most once per difference per session (tracked in `$.store`).
- `/skin`: refuses to write when the session is behind the file, schedules the reload, and asks to run `/skin` again.

Known limits:

- In a stale session, any other settings write (`/config`, another plugin) can still clobber outside edits. Restarting those sessions is the only fix.
- An automatic reload leaves a `/reload-plugins` line in the transcript.
- `tests/status.test.tsx` has 7 type errors that predate this work.
